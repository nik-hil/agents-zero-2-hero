# v0.2-new-tools — File tools

> **Pillar:** 🔧 Toolkit
> **Adds:** `list_files`, `read_file`, `write_file`
> **Builds on:** `v0.1-basic-tool`

## The idea

To work on a codebase an agent needs hands and eyes on the filesystem — but you
don't want it wandering your whole disk. This lesson adds three file tools that
are all **sandboxed to a workspace directory** and reject any path that resolves
outside it.

## What changed vs. the previous tag

```bash
git diff v0.1-basic-tool..v0.2-new-tools --stat
```

- `list_files`, `read_file`, `write_file` functions.
- Matching entries in `TOOL_SCHEMAS` so the model knows they exist.
- Each is registered in the `TOOLS` dict.

## Walkthrough

Every tool resolves the requested path against `WORKSPACE` and checks
`is_relative_to(WORKSPACE)` before touching anything — this is the core
path-traversal guard that keeps `../../etc/passwd` out. `write_file` also
supports overwrite vs. append and creates parent directories as needed.

## Try it

```bash
git checkout v0.2-new-tools

```

## Takeaways

- Give tools the *minimum* reach they need — here, one workspace directory.
- Validate and resolve paths before every filesystem operation.
- Each new tool needs three things: the function, a schema entry, and a `TOOLS` registration.
