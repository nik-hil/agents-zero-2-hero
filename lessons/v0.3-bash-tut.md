# v0.3-bash-tut — A guarded shell tool

> **Pillar:** 🔧 Toolkit
> **Adds:** `bash` (allowlisted) + Docker
> **Builds on:** `v0.2-new-tools`

## The idea

A shell is the most powerful tool you can hand an agent — and the most
dangerous. This lesson adds a `bash` tool that is deliberately constrained: it
parses the command, allows only an explicit set of programs, refuses absolute
paths and `..`, never runs through a real shell (`shell=False`), and runs inside
a Docker container for a second layer of isolation.

## What changed vs. the previous tag

```bash
git diff v0.2-new-tools..v0.3-bash-tut --stat
```

- `bash()` tool with an `ALLOWED_COMMANDS` allowlist and argument checks.
- `Dockerfile` + `docker-compose.yml` for a containerized demo.

## Walkthrough

The command string is split with `shlex.split` (so no shell metacharacters are
interpreted), the program name is checked against the allowlist, and every
argument is rejected if it starts with `/` or contains `..`. Execution uses a
locked-down `env` (minimal `PATH`, `HOME` set to the workspace) and a timeout.
Running the whole thing in Docker means even a bypass is contained.

## Try it

```bash
git checkout v0.3-bash-tut
docker compose up --build
```

## Takeaways

- Prefer an **allowlist** ("only these are permitted") over a blocklist.
- `shell=False` + `shlex.split` avoids an entire class of shell-injection bugs.
- Defense in depth: allowlist *and* a container, not one or the other.
