# v0.1-basic-tool — A minimal agent loop with one tool

> **Pillar:** 🔄 Agent Loop
> **Adds:** `execute_code` + `finish`
> **Builds on:** _(nothing — this is the beginning)_

## The idea

An LLM on its own can only produce text. It becomes an *agent* the moment you
let it (1) call tools and (2) see the results, in a loop. This lesson is the
smallest possible version of that: two tools — `execute_code` to run Python and
`finish` to signal the task is done — and a loop that keeps calling the model
until it finishes.

## Walkthrough

The loop is the whole point:

1. Send the conversation plus the tool schemas to the model.
2. If the model asks for a tool, run it and append the result to the messages.
3. If the model calls `finish`, return its answer and stop.
4. Cap the number of iterations so a confused model can't loop forever.

`execute_code` writes the code to a temp file inside a dedicated workspace and
runs it with a timeout, capturing stdout/stderr. `finish` is a *sentinel* tool:
it carries no side effect, it just tells the harness "I'm done, here's the
answer."

## Try it

```bash
git checkout v0.1-basic-tool
python coding_agent.py
```

## Takeaways

- An agent = a model + a tool-calling loop + a stop condition.
- A "finish" tool is a clean way to let the model end the loop deliberately.
- Always bound the loop with a max-iterations guard.
