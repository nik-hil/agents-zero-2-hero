# v0.8-memory — Persistent memory and context

> **Pillar:** 🧠 Context & Memory
> **Adds:** `Memory` (AGENTS.md injection + MEMORY.md + `remember` tool) and `SessionStore`
> **Builds on:** `v0.7-hooks`

## The idea

Until now the agent woke up with amnesia every run. Real agents remember three
different things, and **all three are just files you read into the prompt**:

| Kind | File | Who writes it | When it's read |
|------|------|---------------|----------------|
| **Project context** | `AGENTS.md` / `CLAUDE.md` | a human | injected into the system prompt every run |
| **Persistent memory** | `MEMORY.md` | the agent, via the `remember` tool | injected into the system prompt every run |
| **Session** | `.agent_sessions/<name>.json` | the harness | replayed when you resume |

That's the whole lesson: memory = files + a tool to write them + injecting them
back into the prompt. No database, no magic.

## How to understand this lesson

1. **`memory.py`** — two small classes:
   - `Memory` reads `AGENTS.md` (`load_context`), reads/appends `MEMORY.md`
     (`load_memory` / `remember`), and combines them into `system_addendum()` —
     the text glued onto the system prompt.
   - `SessionStore` saves/loads a plain transcript (`save` / `load`) and renders
     it for the prompt (`as_text`).
2. **`coding_agent.py`**:
   - near the top, `MEMORY` and `SESSIONS` are created at the **repo root**
     (`WORKSPACE.parent`) — deliberately *outside* the agent's scratch workspace,
     so the files persist and stay human-editable;
   - `run_agent` appends `memory.system_addendum()` to the system prompt (look for
     `# Memory`), and, when `resume=True`, replays a saved transcript;
   - a new `remember` tool lets the model save a note mid-task.
3. **`tests/test_memory.py`** — each test is a tiny spec (remember+load, context
   read, addendum combine, session round-trip), all in a temp dir.

## Try it

```bash
# Run once: the agent remembers a fact and writes notes.txt
python coding_agent.py
cat MEMORY.md                 # the remembered note persisted here

# Run again resuming the same session — prior transcript is injected as context
AGENT_SESSION=demo AGENT_RESUME=1 python coding_agent.py

# Edit project context and watch it reach the agent
echo "- Always add a docstring to new functions." >> AGENTS.md
python coding_agent.py        # note: "[memory] injected N chars of context/notes"

# Offline unit tests
python -m unittest tests.test_memory -v
```

`MEMORY.md` and `.agent_sessions/` are git-ignored (runtime state); `AGENTS.md` is
committed because it's human-authored project context.

## Takeaways

- Memory isn't magic — it's **files read into the prompt** plus a tool to write them.
- Keep memory **outside** the agent's scratch workspace so it persists and humans
  can edit it.
- Context (human-authored) and memory (agent-authored) are different sources that
  both land in the system prompt.
