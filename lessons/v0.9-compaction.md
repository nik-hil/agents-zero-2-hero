# v0.9-compaction — Context compaction

> **Pillar:** 🧠 Context & Memory
> **Adds:** `Compactor` — summarize old turns when the history exceeds a budget
> **Builds on:** `v0.8-memory`

## The idea

Every iteration the agent appends messages: its thinking, tool calls, and
(often huge) tool results. Left alone, `messages` grows until it overflows the
model's context window — the run crashes or silently degrades. Compaction keeps
it bounded: when the history gets too big, **summarize the older middle into one
short note** and keep only what matters:

```
[ system prompt ] [ original task ] [ SUMMARY of the middle ] [ recent turns ]
```

Memory (v0.8) was about remembering *across* runs; compaction is about surviving
*within* one long run.

## How to understand this lesson

1. **`compaction.py`**:
   - `estimate_size()` measures the history in **characters** (~4 chars/token) —
     no tokenizer needed.
   - `Compactor.maybe_compact()` is the whole feature: if under `max_chars`, it's
     a no-op; otherwise it preserves the system prompt + the original task, folds
     the middle into a summary, and keeps the last `keep_recent` messages.
   - Two summarizers: `heuristic_summarizer` (offline, keeps the recent tail — used
     in tests) and `llm_summarizer(client, model)` (asks the model to summarize —
     the default in real runs).
2. **`coding_agent.py`** — `maybe_compact()` runs at the **top of every loop
   iteration**, before the model call (search for `[compaction]`). The threshold
   comes from `AGENT_MAX_CONTEXT_CHARS`.
3. **`tests/test_compaction.py`** — specs for: no-op under budget, size shrinks,
   system/task/recent preserved, and — important — the result contains **no
   tool/tool_call messages**.

## The one subtlety: valid requests

You can't just drop random messages: an assistant message with `tool_calls` must
be followed by matching `tool` results, or the API rejects the request. So
compaction folds the entire middle (including all tool traffic) into **plain
text** and only keeps clean user/assistant text in the recent tail. The rebuilt
list is therefore always a valid request.

## Try it

```bash
# Force a low budget so compaction triggers as the conversation grows:
AGENT_MAX_CONTEXT_CHARS=5000 python coding_agent.py
# → watch for: [compaction] history summarized -> now N messages, ~M chars

# Offline unit tests
python -m unittest tests.test_compaction -v
```

### Careful: don't set the budget below your fixed overhead

The system prompt + injected memory (AGENTS.md/MEMORY.md) + the task form a
**floor** the history can never drop below — often ~3000 chars. If you set
`AGENT_MAX_CONTEXT_CHARS` *below* that floor, compaction would fire every single
turn and keep discarding the agent's short-term working memory — so it forgets
what it just did and loops (e.g. calling `list_files` over and over) instead of
finishing. `Compactor` guards against the worst of this: when there's nothing left
in the "middle" to summarize, it stops (a no-op) rather than churning. Still, pick
a budget **above** your overhead so compaction only kicks in once real history has
accumulated. That's why the command above uses 5000, not 1500.

## Takeaways

- Long runs need a bound on context; compaction provides it by summarizing.
- Measure in characters if you want to stay dependency-free; swap in a real
  tokenizer later if precision matters.
- Compact at safe boundaries — never leave an orphaned tool_call/tool pair.
