# v0.13-verify-loop — Verification loop

> **Pillar:** 🔄 Agent Loop
> **Adds:** `run_tests` tool — run → read failures → fix → rerun until green
> **Builds on:** `v0.12-subagents`

## The idea

The agent could already write and edit code. The missing half is letting it
**check its own work**. `run_tests` runs the suite and hands back pass/fail plus
output as data the model can read. With that, the agent closes the loop:

```
run_tests → read failure → edit code → run_tests → ... until green → finish
```

That's the difference between "generate code and hope" and "generate, verify,
fix". It's a fitting finale: the harness is now good enough to *iterate toward a
working result on its own*.

## How to understand this lesson

1. **`verify.py`** — `run_tests(workspace)` shells out to
   `python -m unittest discover` in the workspace and returns
   `{passed, returncode, output}` (output tail kept small so it doesn't flood the
   context). Nothing agent-specific — it just runs tests and returns the result.
2. **`coding_agent.py`** — a `run_tests` tool wraps it, plus a system-prompt rule:
   *if there are tests, run them, and on failure fix and rerun until they pass
   before finishing.* The `AGENT_VERIFY=1` demo seeds a buggy `calc.py`
   (`add` subtracts) and a failing `test_calc.py`, then asks the agent to fix it.
3. **`tests/test_verify.py`** — failing suite → `passed=False`, passing suite →
   `passed=True`, and a fix-after-failure test.

## The subtle bug worth knowing: stale bytecode

When the agent edits `calc.py` and reruns, Python might reuse a cached
`__pycache__/*.pyc` from the previous run — because CPython validates the cache by
source **size + mtime (whole seconds)**, and a quick edit of the same length in
the same second looks unchanged. The fix would then appear to "not work". So
`run_tests` clears `__pycache__` and sets `PYTHONDONTWRITEBYTECODE=1` before each
run, guaranteeing the test sees the current source. (This actually bit us while
building the lesson — a good reminder that the harness must be careful about the
environment it runs code in.)

## Try it

```bash
AGENT_VERIFY=1 python coding_agent.py
# → run_tests (FAIL: add(2,3) != 5) → edit calc.py → run_tests (OK) → finish

python -m unittest tests.test_verify -v
```

## Takeaways

- A feedback tool (`run_tests`) turns the agent from a generator into an iterator.
- Return results as **data** (pass/fail + output) so the model can act on them.
- Mind the environment: caches and stale state can make a real fix look broken.
