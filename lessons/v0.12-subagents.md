# v0.12-subagents — Subagents

> **Pillar:** 🤝 Swarm
> **Adds:** `spawn_subagent` — depth-guarded delegation to a fresh child agent
> **Builds on:** `v0.11-mcp`

## The idea

One agent, one context. As a task grows, that single context fills with detail
from every sub-step and the agent loses the plot (and hits the window). The fix:
**delegate**. The main agent spawns a *subagent* — a fresh `run_agent` with its
own clean message history and the same tools — hands it a scoped subtask, and gets
back just the answer. The messy detail stays in the child's context, not the
parent's.

It's the same trick as skills and compaction from a different angle: **keep each
context small and focused**.

## How it works

`spawn_subagent(task)` is just `run_agent` calling itself:

```
parent run_agent (depth=0)
   └─ spawn_subagent("do X")
         └─ child run_agent (depth=1)   # fresh messages, same tools/policy
               └─ finish("X done")      # returns up to the parent
```

Two things make this safe and useful:

- **Isolated context** — the child starts fresh, so its intermediate steps never
  touch the parent's history. The parent only sees `{"subagent_result": ...}`.
- **Depth guard** — `depth` / `max_depth` bound the recursion (default
  `max_depth=1`: the parent may spawn children; children may not spawn). Without
  this, agents could spawn agents forever.

The child **shares** policy and workspace: same `permissions`, `hooks`, `memory`,
and the same files on disk — so a subagent still can't do what plan mode forbids,
and its file edits are visible to the parent.

## How to understand this lesson

1. **`coding_agent.py`**:
   - `run_agent` gained `depth` / `max_depth`;
   - `_spawn_subagent` (a closure) recursively runs a child and returns its answer,
     with the depth guard;
   - it's only advertised when `depth < max_depth`;
   - the loop now also returns a clean error for an **unknown tool** instead of
     crashing — which is what happens if the model tries to spawn past the limit.
2. **`tests/test_subagents.py`** — a fake model scripts parent→spawn→child→finish
   and asserts the child actually ran (by counting model calls), plus a depth-guard
   test.

## Try it

```bash
AGENT_SUBAGENT=1 python coding_agent.py
# → [subagent] depth 1: creating greet.txt ...
#   (child runs its own loop, writes the file, returns)
#   Final result: ... (parent reports the child's result)

python -m unittest tests.test_subagents -v
```

## Takeaways

- Delegation keeps each agent's context small and on-task; the parent sees results,
  not the child's scratch work.
- Always bound recursion (`max_depth`) — unbounded spawning is a footgun.
- Subagents share policy and workspace but not conversation — isolation is the point.
