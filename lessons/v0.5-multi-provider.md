# v0.5-multi-provider — Multiple LLM providers

> **Pillar:** 🔌 Providers
> **Adds:** provider switch (OpenRouter + DigitalOcean) + first unit tests
> **Builds on:** `v0.4-edit-tool`

## The idea

An agent never really talks to a *vendor* — it talks to the OpenAI
chat-completions **API shape**. OpenRouter and DigitalOcean Serverless Inference
both expose that shape, so "support both" is just picking a bundle of three
things: `base_url`, which API key to read, and the model slug. Everything else —
the loop, the tools — stays identical.

## What changed vs. the previous tag

```bash
git diff v0.4-edit-tool..v0.5-multi-provider --stat
```

- `client.py`: a `PROVIDERS` table + `get_provider()` / `get_model()` /
  `get_client()`, selected by the `LLM_PROVIDER` env var (`LLM_MODEL` overrides).
- `coding_agent.py`: uses `client.get_model()` instead of a hardcoded slug.
- `tests/test_client.py`: the repo's first unit tests (offline, no key).

## Walkthrough

`client.py` keeps one config bundle per provider:

```python
PROVIDERS = {
    "openrouter":   {"base_url": "https://openrouter.ai/api/v1",   "api_key_env": "OPENROUTER_API_KEY",         "default_model": "openai/gpt-5.6-luna"},
    "digitalocean": {"base_url": "https://inference.do-ai.run/v1", "api_key_env": "DIGITALOCEAN_INFERENCE_KEY", "default_model": "openai-gpt-5.6-luna"},
}
```

Note DigitalOcean model IDs use **hyphens** (`openai-gpt-5.6-luna`), not slashes.
Pick a model that supports Chat Completions + tool calling — a few of DO's newest
models are Responses-API only and won't work with `chat.completions.create()`.

## Try it

```bash
# Configure a provider in .env (never commit keys)
python client.py                 # prints provider + model, says hello
python -m unittest discover -s tests -v   # 7 offline tests
```

## Takeaways

- Provider choice is infrastructure, not logic — swap `base_url` + key + model.
- Keep model selection in one place (`get_model()`) so every caller follows.
- Read secrets from the environment / `.env`; never hardcode or commit them.
