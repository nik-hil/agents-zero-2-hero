# v0.11-mcp — An MCP client

> **Pillar:** 🔧 Toolkit
> **Adds:** `MCPClient` (stdio JSON-RPC) + a bundled example server + tool mounting
> **Builds on:** `v0.10-skills`

## The idea

So far every tool was hand-written inside this repo. The **Model Context
Protocol (MCP)** is the open standard for using tools you *didn't* ship: an
external **server** exposes tools, and your harness (the **client**) discovers
and calls them. Connect once and the agent gains a whole new toolset — GitHub,
a database, a browser — without you writing any of it.

The punchline: an MCP tool becomes the *exact same* `(schema, callable)` pair the
harness already uses, so it drops into `TOOLS` / `TOOL_SCHEMAS` next to the
built-ins with zero special-casing in the loop.

## The protocol, minimally

MCP's stdio transport is **newline-delimited JSON-RPC 2.0** over a subprocess's
stdin/stdout. Three calls matter:

```
initialize        handshake (client says hello, server states capabilities)
tools/list        server returns its tool definitions (name, description, inputSchema)
tools/call        run one tool with arguments, get back content
```

That's it — no SDK required.

## How to understand this lesson

1. **`mcp_servers/echo_server.py`** — a tiny *server* (pure stdlib) so the lesson
   is self-contained. It exposes `echo` and `add`. Read `handle()` to see the
   three methods. Try it raw:
   ```bash
   echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | python mcp_servers/echo_server.py
   ```
2. **`mcp_client.py`** — the *client*:
   - `start()` spawns the server and does the `initialize` / `initialized` handshake;
   - `_request()` is the JSON-RPC round-trip (write a line, read until the matching id);
   - `list_tools()` / `call_tool()` are the two MCP methods;
   - `to_openai_schemas()` + `make_proxies()` convert remote tools into the
     harness's `(schema, callable)` shape, namespaced with an `mcp__` prefix.
3. **`coding_agent.py`** — `run_agent` gained `extra_tools` / `extra_schemas`, merged
   with the built-ins (`tools_map`, `schemas`). With `AGENT_MCP=1`, `__main__`
   connects to the echo server and mounts its tools.

## Try it

```bash
AGENT_MCP=1 python coding_agent.py
# → [mcp] connected; tools: ['echo', 'add']
#   Tool call: mcp__add {'a': 21, 'b': 21}   <- a tool from the external server
#   Final result: ... 42

python -m unittest tests.test_mcp -v   # spawns the real server, no key needed
```

Point it at a *different* server by changing the command passed to `MCPClient`
(any program that speaks MCP over stdio).

## Notes & caveats

- MCP tools are namespaced (`mcp__add`) to avoid clashing with built-in tool names.
- They're **not** in the permission read-only list, so they're treated as
  mutating — gated by mode (blocked in `plan`). That's the safe default for tools
  whose effects you don't control.
- This is stdio only; real clients also support HTTP transport and richer
  capabilities (resources, prompts) — same JSON-RPC idea.

## Takeaways

- MCP = a standard way to borrow tools; the client just does `initialize` →
  `tools/list` → `tools/call`.
- Adapt external tools to your harness's tool shape and they need no special path.
- Namespace and gate foreign tools — you didn't write them.
