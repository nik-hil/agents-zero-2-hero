# v0.4-edit-tool — Precise edits and search

> **Pillar:** 🔧 Toolkit
> **Adds:** `edit_file` + `code_search` (ripgrep)
> **Builds on:** `v0.3-bash-tut`

## The idea

Rewriting a whole file to change one line is wasteful and error-prone. Real
coding agents make **surgical edits** and **search** the codebase to find what
to change. This lesson adds both: `edit_file` does an exact search/replace, and
`code_search` finds patterns across files.

## What changed vs. the previous tag

```bash
git diff v0.3-bash-tut..v0.4-edit-tool --stat
```

- `edit_file(filepath, search_text, replace_text)` — exact, first-occurrence replace.
- `code_search(pattern, file_pattern, context_lines)` — ripgrep if available, else a Python fallback.

## Walkthrough

`edit_file` reads the file, verifies `search_text` actually exists (and returns
a helpful error with a snippet if it doesn't), then replaces only the **first**
occurrence — predictable and safe. `code_search` shells out to `rg` for speed
when it's installed and otherwise falls back to a pure-Python scan, so the tool
works everywhere. Both stay inside the workspace guard from earlier lessons.

## Try it

## Takeaways

- Exact-match, single-occurrence replaces make model edits predictable.
- Return actionable errors (e.g. "search_text not found") so the model can retry.
- Provide a fallback path so a tool degrades gracefully when a binary like `rg` is missing.
